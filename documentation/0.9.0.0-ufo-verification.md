## 2. Version source of truth and surface audit

The single source of truth is `m1_csrc/m1_fw_update_bl.h`:
`FW_VERSION_MAJOR/MINOR/BUILD/RC = 0/9/0/0` (lines 38–41) and
`FW_VERSION_FORK_TAG "UFO"` (line 44). `FW_BUILD_LABEL` (lines 49–53) is
composed from those macros (`FW 0.9.0.0-UFO`) so the display label cannot drift.
The fork tag is display-only: it is excluded from the 4-field numeric compare in
the rollback gate and from the `S_M1_FW_CONFIG_t` image metadata (header comment,
lines 42–43), preserving the wire/image format.

Surfaces that are **hardware identity, not version carriers** (documented, not
changed — changing them would reclassify this unit):

- **USB device descriptor** (`USB/Core/Src/usbd_desc.c`): product strings
  `MTEKM1_MSC_CDC HS/FS` (lines 46–47) and `bcdDevice 2.00` (line 152) identify
  the composite MSC+CDC function across all firmware revisions. No firmware
  version is carried on the USB descriptor; the version surfaces are the CLI
  (`version`/`status`), boot screen, About screen, and artifact/manifest names.
- **CubeMX project file** `MonstaTek_M1_v0800.ioc`: the hardware configuration
  file's on-disk name (referenced accurately by `docs/hardware.md:22`); it pins
  pin/peripheral configuration, not the firmware version. Renaming it would
  churn CubeMX round-trips with no version benefit.
- Historical comments inside runtime sources (e.g. the port note in
  `m1_csrc/m1_feedback_hw_adapter.c:10-11` describing the 0.8.0.5-era base that
  file was ported against) describe merge history, not the running version, and
  are out of bounds for this content-only unit (zero `.c/.h` diffs).
