# Release notes — M1 firmware v0.9.0.0-UFO

**Release date:** 2026-11-19
**Firmware identity:** `FW 0.9.0.0-UFO` (artifact stem `M1_v0.9.0.0-UFO`)
**Base:** based on upstream MonstaTek M1 **0.8.1.0**, pinned at
`2af1f8a339dbe629f36a0551de4293b161179b71` and adopted via the merge-1
ancestry graft (see [DEVELOPMENT.md — Merge Policy](../../DEVELOPMENT.md) and
the [merge ledger](../merge/LEDGER.md)).

This is the fork's first release on the adopted upstream base. The version
0.9.0.0 opens the fork's own namespace above both prior lines: the rollback
comparator accepts it over legacy **0.8.11** (the immutable archive tag) and
upstream **0.8.1.0**, as frozen in issue #36 and pinned by the comparator host
test (`tools/test_fw_version_compare.py`). The `-UFO` suffix is a display-only
fork tag — it appears in the boot log, the About box, the CLI `version`
output, and artifact names, and is excluded from the numeric image-metadata
compare and the `S_M1_FW_CONFIG_t` wire format.

The whole fork-vs-upstream difference at this release is audited row by row in
the [release delta audit](../merge/DELTA_AUDIT.md): every file in
`git diff upstream/main..main` maps to a merge-ledger disposition or an
explicit, referenced change — zero unexplained rows, machine-checked by
`python tools/check_delta_audit.py`.

## Carried features (with references)

### Foundation and toolchain (merge 1 & 2)

- Upstream 0.8.1.0 base adoption with ancestry graft; legacy v0.8.11 archived
  under the immutable `legacy/v0.8.11` tag; EOL normalization and fork version
  freeze (#36, #37; PRs #47/#48/#50).
- Merge ledger dispositioning every legacy fork-changed file (#38, PR #51) and
  scoped `-Werror` warning hygiene over app sources (#39, PR #53).
- Version-derived, cross-platform canonical build with interchangeable CRC
  emitters (srec_cat + pure-Python), CRC-embedded artifacts and release
  manifest (#40, PR #59); Windows verification adapters as repo artifacts
  (#49, PR #53); Linux/case-sensitivity build fixes (#46, PR #56; C23 literal
  fix PR #57).
- Port-stability carry: Sub-GHz Rx GPDMA double-buffered deferred-context
  ingestion, SD filename buffer widening, radio SPI hang guards (#52, PRs
  #54/#55).
- ROM DFU entry (strap/request/recovery-screen offer) and application boot
  failsafe with boot/swap accounting (#41, PRs #61/#62).
- Console diagnostics: USB CDC RX drop/high-watermark counters, log capture,
  fork CLI additions and re-homed `mtest` IDs (#44, PRs #64/#65).

### Features & settings (merge 3)

- Durable user-settings store on SD (`0:/System/settings.cfg`, atomic
  tmp/bak promotion, tolerant parse, CRC-checked) — the substrate under every
  settings screen (PR #66).
- LCD & Notifications and System settings screens: brightness with live
  preview, screen timeout (incl. Off), LED notification gating, device name,
  storage info, reset-to-defaults (#4 and the non-RTC part of #7, PR #68).
- RTC date/time setting with validation and leap-year handling, current time
  in the System screen (#7 completion, PR #71).
- Universal Remote consolidated onto the upstream IRMP stack: streaming
  `.ir` loader with strict-skip (#43 part 1, PR #72), SD-card IR file browser
  with dashboard/pagination/search and empty-state guidance (PR #75),
  favorites/recent lists and explicit cycle-all-in-category action (PR #78);
  golden-decode regression over the IR capture corpus.
- Sub-GHz Radio Settings: modulation (OOK/2-FSK/4-FSK/GFSK), RX bandwidth,
  FSK deviation, TX power, frequency override with region gating, persisted
  and applied before record/replay (#3, PR #81).
- Crypto foundation: AES-256-CBC + AES-CMAC (published vectors), UID-derived
  keys, mandatory STM32H5 hardware RNG with sticky-failure refusal — no
  fallback (#42 part 1, PR #82).
- WiFi credentials at rest: optional encrypted column on the versioned
  `saved_networks.csv` (per-record random IV, CMAC integrity, tamper
  degradation, PSK zeroization) plus the honest threat model (#42 part 2,
  PR #85).
- Live ESP32 firmware feature gate: four states (older/equivalent/newer/
  absent), never trusting the cached record (PR #86).
- WiFi join flow: saved/scan pickers, masked PSK editor, gated join transport,
  boot-time reconnect attempt, ESP-side `CTRL_REQ_CONNECT_AP` handler (#42
  completion, PR #88).
- Bluetooth advertisement config editor: verified payload presets (Apple
  proximity, Samsung Easysetup, Microsoft Swift Pair, flags+name, custom from
  SD), interval presets, start/stop gated on the external ESP32 firmware
  advertising the `adv` verb (#11, PR #93).

## Dropped or superseded fork work (with references)

- **Legacy IR stack superseded**: the fork's whole-file `.ir` parser, its
  64-command cap, and its aliasing protocol map are not ported; upstream's
  `ir_protocols_mapping_table` and IRMP data layer are the single foundation
  (#43, PRs #72/#75/#78; ledger rows for `m1_ir_universal.c` — dropped).
- **Second WiFi credential store dropped**: legacy `m1_wifi_cred.c` is not
  imported; encrypted credentials ride the existing `saved_networks.csv` with
  `FMT_VER` unchanged (#42, PR #85; ledger disposition intentionally-dropped).
- **Zero-Warning whole-tree restyle dropped**: the legacy tree-wide clang-format
  pass that poisoned upstream merges was not carried; the genuine warning fixes
  were recovered from it (34 `recovered-warning-fix` ledger tags) and warning
  hygiene is now enforced by the scoped `-Werror` gate instead (#39, PR #53).
- **FCC test placeholders removed**: legacy FCC test placeholder code and
  associated dead code stay dropped (#28; ledger disposition
  intentionally-dropped).
- **Legacy release line closed**: the fork's 0.8.x line ends at the archived
  `legacy/v0.8.11` tag; 0.9.0.0-UFO supersedes it on the upstream base (#36).
  Legacy release notes remain available in the immutable tag history
  (`git show legacy/v0.8.11:CHANGELOG.md`).
- **Legacy planning docs dropped**: `ROADMAP.md` and the legacy
  `ARCHITECTURE.md` feature-status matrix were not re-landed; the ledger keeps
  their dispositions and the issues tracker owns the roadmap (#38, PR #51).

## Known limits

- **Application-level failsafe scope.** The boot-time integrity check runs in
  the application (`startup_boot_failsafe()`), not in a ROM bootloader:
  detection and accounting are automatic, containment is not. On a CRC failure
  the device shows the `FW CORRUPT!` banner and a bounded USB DFU offer, but
  the unvalidated image is **not** prevented from running after the offer
  expires or is declined, and automatic failed-boot rollback (bank swap
  without the user keypress) is not implemented — the manual BACK+DOWN
  interactive rollback remains the alternate-bank path, with bounded swap
  accounting. Supported recovery: the SD-card update path, the DFU
  strap/request, the recovery-screen offer, and the interactive rollback
  (details: [firmware-update documentation](../protocols/firmware-update.md);
  on-device qualification is the open #41 hardware gate).
- **Issue #22 outcome — ISR load under Sub-GHz capture.** The deferred
  RTOS-context ingestion proposed in #22 landed for the **record** path:
  GPDMA1 double-buffered RAW capture replaced the per-edge `TIM1_CC` ISR
  while recording, with the DMA ISR queueing completed blocks and notifying
  the record task (#52, PR #55). The **scanner** keeps the per-edge interrupt
  path by design, so the original #22 concern is resolved where it was
  measured (recording under heavy load), not abolished everywhere. #22 is
  closed as carried.
- **ESP32-coupled features need paired external firmware.** WiFi join
  requires an ESP32 console image reporting `ESPFW 1.1.0.0` or newer; BLE
  advertising requires the not-yet-released image carrying the `adv` verb
  (`ESPFW 1.2.0.0`) — until then the editor configures and persists, and
  Start refuses with "ESP update required", sending nothing (#92).
- **Hardware acceptance is archived, not yet executed.** The on-device
  acceptance items for this release's features are aggregated in the archived
  [smoke checklist](0.9.0.0-ufo-smoke-checklist.md) and tracked as open
  follow-up issues (#67, #70, #77, #80, #83, #87, #92, plus #60/#63); host
  suites and review gates passed, but no on-device claim in this release is
  qualified yet.
- **Vendored ESP SPI driver defects are tracked, not fixed** (#89 mutex error
  paths, #90 1-byte OOB on max-length reads) — pre-existing upstream vendor
  debt explicitly deferred from PR #88.
- **Host-test coverage is the wired set.** `scripts/run_host_tests.sh` runs
  exactly the suites wired into it (CI: `.github/workflows/host-tests.yml`);
  the pre-existing host corpus outside that list is a separate concern, and
  there is no other CI.

## IR starter database (release asset)

The release ships a **starter IR database** as a downloadable asset (not in
git): a curated category set from
[Lucaslhm/Flipper-IRDB](https://github.com/Lucaslhm/Flipper-IRDB) at the
pinned commit **`d126fb1b6f1e114c52b4a8c19839ea65e3a9c24d`** (2026-04-12
snapshot):

- Categories: `TVs`, `ACs`, `Audio_and_Video_Receivers`,
  `Streaming_Devices`, `Projectors` — 809 `.ir` files, 3,583,934 bytes
  unzipped.
- License: the repository is **CC0 1.0 Universal**; the legal code and the
  attribution record ship in
  [irdb-attribution.md](irdb-attribution.md).
- **Pre-boundary caveat (upstream's own scope statement):** Flipper-IRDB's
  README states that commits prior to
  `2319685f2cbf0cd3f809609622cade14d24fb819` (2025-08-07, the commit that
  introduced the LICENSE) are **not covered** by the CC0 grant. This snapshot
  is pinned after that boundary, but individual `.ir` files whose content
  predates it may rely on the upstream maintainers' continued CC0 intent
  rather than a grant that existed when the file was first contributed. The
  attribution record carries this caveat verbatim.
- Why not `UberGuidoZ/Flipper`: that repository's `Infrared/` set is licensed
  **GNU GPL-3.0** (its LICENSE file), which is incompatible with this
  project's permissive redistribution of a standalone database asset; it is
  not used.
- **Packaging (reproducible):** `sh scripts/fetch_ir_starter_db.sh` downloads
  the repository as a single source tarball at the pinned commit (codeload —
  the pin is immutable, so one request is as reproducible as per-file raw
  downloads), extracts exactly the five categories, prunes non-`.ir` files,
  verifies the extracted set byte-for-byte against the GitHub tree API
  listing for the same commit, and packs `IR/…` under the SD-card convention
  into `artifacts/M1_IRDB_starter_d126fb1b.zip` (deterministic: sorted
  entries, fixed timestamps, no host attributes) for upload as the release
  asset. Extract the zip to the SD-card root so `IR/` sits beside `System/`;
  see [IR database provisioning](../ir-provisioning.md).
